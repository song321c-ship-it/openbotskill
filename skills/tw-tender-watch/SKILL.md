# 台灣標案監測與初篩

分兩半：
- **第一到第四節**給「標案哨兵」（輕量模型）：去哪查、怎麼篩、怎麼記、怎麼轉交。哨兵只抓、只記、不判斷要不要投。
- **第五到第七節**給「招標文件分析師」：新案初篩、符合度星等、截標提醒。

所有網址 2026-11-06 實測可用、不需登入、沒有驗證碼、是靜態網頁。

## 一、使用者的條件檔

`~/OpenBot/Shared/標案/關注條件.md`（使用者填，哨兵只讀）：

```
關鍵字：資訊系統、網站建置、維運（每行一組，同義詞用頓號）
排除字：清潔、保全
機關：（可空白）臺北市政府、國立臺灣大學
標的分類：勞務（工程／財物／勞務，可多選）
預算範圍：100 萬～1,000 萬（可空白）
履約地點：（可空白）臺北市、新北市
```

`公司資格.md` 由標案經理維護（營業項目、資本額、實績、證照、可承接金額上限），分析師初篩時用。

## 二、查詢網址（政府電子採購網 web.pcc.gov.tw）

### 當日招標公告（主要來源）

```
https://web.pcc.gov.tw/prkms/tender/common/basic/readTenderBasic?firstSearch=true&searchType=basic&isBinding=N&isLogIn=N&level_1=on&tenderType=TENDER_DECLARATION&tenderWay=TENDER_WAY_ALL_DECLARATION&pageSize=100&dateType=isNow&tenderName={關鍵字}
```

- `dateType=isNow`＝當天公告；`isSpdt`＝還在等標期內（第一次執行、或要補抓時用）
- 依機關查：把 `tenderName=` 換成 `orgName={機關名}`
- 依標的分類：加 `&radProctrgCate=RAD_PROCTRG_CATE_1`（工程）、`_2`（財物）、`_3`（勞務）
- 一頁最多 100 筆；超過時翻頁加 `&d-49738-p=2`、`3`……
- **每個關鍵字、每個機關各查一次**；關鍵字用網址編碼（瀏覽器或抓網頁工具會自動處理中文）
- 結果表格欄位：機關、案號、標案名稱、招標方式、採購性質、公告日、截止投標、預算金額；標案名稱有時在連結的 title 屬性或頁面腳本字串裡，要整段讀
- 每列有連到單案的網址（`/prkms/urlSelector/common/tpam?pk=…`），照抄頁面上的連結，不要自己組

### 當日更正公告（追蹤中的案子有沒有改截止日、改規格）

```
https://web.pcc.gov.tw/prkms/tender/common/updated/readTenderUpdated?firstSearch=true&searchType=updated&isBinding=N&isLogIn=N&level_1=on&tenderType=TENDER_DECLARATION&tenderWay=TENDER_WAY_ALL_DECLARATION&pageSize=100&dateType=isNow&tenderName={關鍵字}
```

### 備援
- 今日招標總表 `https://web.pcc.gov.tw/prkms/today/common/todayTender`：沒有預算欄，全文很長（約 20 多萬字），要分段讀；主要來源讀不到時才用
- 不能用：採購網 RSS（已失效）、官方招標 XML 資料集（落後一個月以上而且不是全量）、公開閱覽查詢（要送表單）
- g0v 標案 API 只准個人非營利使用，這個技能不用

## 三、記錄：用 OpenBot 共用資料庫（不用整檔重寫）

已看過的標案存在共用資料庫的表 `tender_inbox`，**不要用檔案記已讀**（整檔讀寫容易出錯，也可能卡在安全確認）。工具：`openbot.list_tables`、`openbot.query_data`、`openbot.execute_data`（一次一個 SQL、值一律用 `?` 參數）。

第一次（list_tables 沒有這張表）建立：

```sql
CREATE TABLE tender_inbox (
  pk TEXT PRIMARY KEY,          -- 機關名稱｜案號
  case_no TEXT, org TEXT, name TEXT,
  budget TEXT, deadline TEXT, nature TEXT,
  url TEXT, matched TEXT,       -- 命中的關鍵字或機關
  found_at TEXT,                -- 台灣時間 YYYY-MM-DD HH:mm
  status TEXT                   -- 待初篩／已初篩／略過／排除
)
```

**時間一律台灣時間（UTC+8）**：系統或工具回傳的時間如果是 UTC（結尾 Z 或 +00:00），要加 8 小時再寫入 `found_at`、`published` 與心跳；日期也可能因此跨到隔天。

每次巡邏：
1. 把這次查到、而且通過篩選的標案列成候選
2. `SELECT pk FROM tender_inbox WHERE pk IN (?, ?, …)` 找出已經記過的
3. 沒記過的才是新的：一次寫入多列 `INSERT INTO tender_inbox (pk, case_no, …, status) VALUES (?, …, '待初篩'), (…)`
4. 第一次建表時：只寫入、`status` 一律填「略過」、不轉交（避免把等標期內的舊案全部當新案）

篩選（哨兵照規則做，不判斷值不值得投）：
- 標案名稱含關鍵字（或機關符合）才算候選
- 名稱含排除字的不記
- 有預算範圍時，預算金額在範圍外的不記；預算寫「未公開」的照樣記，`budget` 填「未公開」
- 截止投標已經過了的不記

## 四、轉交與心跳

- 有新案：用 `openbot.tool_call` 的 `send_message` 請「招標文件分析師」執行例行任務「新案初篩」。排程中不能用 test_routine 觸發別的代理，一定用 send_message
- 心跳：每次在 `~/OpenBot/Shared/標案/哨兵心跳.md` 追加一行（讀出整檔、加一行、整檔寫回）：台灣時間｜每個關鍵字查到幾筆｜新增 N 筆｜已轉交／無新增／轉交失敗；讀不到寫「讀取失敗：原因」
- 同一個查詢連續 3 次讀取失敗：呼叫 `openbot.routine_report_failure`（只在第 3 次）

## 五、新案初篩（招標文件分析師）

1. `SELECT * FROM tender_inbox WHERE status = '待初篩' ORDER BY deadline LIMIT 20`
2. 每筆打開 `url`（會轉到 `https://web.pcc.gov.tw/tps/QueryTender/query/searchTenderDetail?pkPmsMain=…` 的單案公告頁），照原文抄：案號、名稱、機關、預算金額與級距、截止投標（日期與時間）、開標時間地點、押標金、廠商資格摘要、履約地點、決標方式、標的分類
3. 對照 `公司資格.md` 給符合度（第六節）
4. 寫進 `標案追蹤.csv`（案號,名稱,機關,預算,截止投標,符合度,狀態=已初篩,公告頁網址）：讀出整檔、加列、整檔寫回；同一案號已在表內就只更新
5. `UPDATE tender_inbox SET status = '已初篩' WHERE pk = ?`
6. 回覆：★★★ 以上的依截止日排列；★★ 以下合併成一行「另有 N 筆符合度低」
7. 招標文件（投標須知、契約、需求書）要登入採購網才能領，**分析師不登入**；要深入評估時請使用者領標後把檔案放進 `案件/{案號}/`

## 六、符合度星等（初篩，不是投標建議）

| 星等 | 條件 |
|---|---|
| ★★★★★ | 標的和公司主要營業項目、過去實績同類；預算在可承接上限內；資格條件看起來都符合；截止日前有足夠準備時間（7 天以上） |
| ★★★★☆ | 同類標的，但有一項要再確認（某張證照、某類實績、專業人員） |
| ★★★☆☆ | 相關但不完全同類，或預算接近上限，或準備時間 3～7 天 |
| ★★☆☆☆ | 只有部分相關，或資格明顯有缺，或準備時間少於 3 天 |
| ★☆☆☆☆ | 名稱命中關鍵字但其實不相關（例如 「資訊」出現在別的脈絡） |

調整：**履約地點不在關注條件的地區**時最多 ★★，理由寫「履約地點在 XX，不在你的關注地區」（哨兵查詢結果看不到地點，地點由分析師在單案頁檢查）；預算超過公司可承接上限時最多 ★★。

每筆寫一句理由，對應到公司資格的哪一項。資格看不出來時寫「待確認：要看投標須知」，不要猜。星等只是幫使用者決定先看哪幾件，**投不投由使用者與標案經理評估決定**。

## 七、截標與更正提醒（分析師每天第一次初篩時一起做）

- 讀 `標案追蹤.csv`，狀態為 已初篩／評估中／準備投標 的案子，**截止投標在 3 天內**的列出來（日期、時間、還剩幾天）
- 用第二節的更正公告網址查追蹤中案子的名稱，有更正公告就寫「有更正，請看公告」並附頁面；截止日改了要更新追蹤表
- 押標金、保證金、等標期與疑義異議期限，**一律以招標文件與公告原文為準**；需要說明法規時引用政府採購法（全國法規資料庫）與「押標金保證金暨其他擔保作業辦法」的實際條文頁，不憑記憶寫數字

## 八、易錯點

- 用 `dateType=isDate` 查日期區間：會混進公告日超過迄日的更正案；當天用 `isNow`。
- 自己組單案網址：一定照查詢結果頁上的連結。
- 用檔案記已讀、每次整檔重寫：改用共用資料庫的 `tender_inbox`。
- 第一次執行把等標期內的舊案全部當新案轉交：第一次只建表、標「略過」。
- 哨兵替使用者判斷值不值得投：哨兵只照關鍵字、排除字、預算範圍篩；符合度是分析師的工作。
- 用 test_routine 轉交：排程中會被擋，用 send_message。
- 名稱命中關鍵字就當相關：「資訊」「維護」這類字很常見，分析師要看標的分類與內容。
