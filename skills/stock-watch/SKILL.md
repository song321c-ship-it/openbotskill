# 個股監測與快評（台股＋美股）

這個技能分兩半：
- **第一到第四節**給「個股哨兵」：怎麼把公司加進清單、去哪裡抓、怎麼記。哨兵只抓、只記、不判讀，只用抓網頁與讀寫檔工具。
- **第五到第七節**給「投資情報分析員」：怎麼判讀利多利空、怎麼給星等。

所有網址都在 2026-11-06 實測可用、不需登入。

## 一、加入追蹤：把使用者的話對應成公司

使用者可能說「台積電」「2330」「TSMC」「NVDA」「輝達」。照這個順序判斷：

1. **四到六位數字**（2330、00878）→ 台股。先查上市名單，查不到再查上櫃名單
2. **英文字母代號**（NVDA、TSM、BRK.B）→ 美股，查 SEC 代號表
3. **中文名稱** → 先比對台股上市、上櫃的「公司簡稱」與「公司名稱」；都沒有，再當成美股的中文俗稱（例如 輝達＝NVIDIA），用英文名到 SEC 代號表找
4. 同時有台股和美股（例如 台積電 有 2330 和 ADR TSM）→ 列出來請使用者選，或兩個都加
5. 對不到、或對到好幾家 → 列出候選請使用者選，**不要自己猜**

| 名單 | 網址 | 用到的欄位 |
|---|---|---|
| 台股上市公司 | https://openapi.twse.com.tw/v1/opendata/t187ap03_L | 公司代號、公司名稱、公司簡稱、英文簡稱 |
| 台股上櫃公司 | https://www.tpex.org.tw/openapi/v1/mopsfin_t187ap03_O | SecuritiesCompanyCode、CompanyName、CompanyAbbreviation |
| 美股代號與 CIK | https://www.sec.gov/files/company_tickers.json | ticker、title、cik_str（CIK 要自己在前面補 0 到 10 碼） |

寫進 `~/OpenBot/Shared/投資/關注清單.md`，一行一家：

```
市場｜代號｜名稱｜CIK（美股才有）
台股｜2330｜台積電｜
美股｜NVDA｜NVIDIA CORP｜0001045810
美股｜TSM｜TAIWAN SEMICONDUCTOR MANUFACTURING CO LTD｜0001046179
```

持股.csv 裡的個股也一起巡（ETF 不巡）。

## 二、巡邏來源

### 台股：公開資訊觀測站重大訊息

| 來源 | 網址 | 說明 |
|---|---|---|
| 即時重大訊息（主要） | https://mopsov.twse.com.tw/mops/web/t05sr01_1 | 靜態網頁，列出**當天全市場**的重訊：公司代號、簡稱、發言日期（民國）、發言時間、主旨。只挑清單上的公司 |
| 證交所 OpenAPI（備援） | https://openapi.twse.com.tw/v1/opendata/t187ap04_L | 同樣是當天全市場；多了「符合條款」「事實發生日」「說明」 |

- 新版的 mops.twse.com.tw 要跑 JavaScript，抓網頁工具讀不到，**一律用 mopsov 或 OpenAPI**
- 識別碼＝公司代號＋發言日期＋發言時間
- 連結：主要來源的頁面本身（當天列表）；情報分析員判讀時再到觀測站找那則的內容

### 美股：SEC 申報（不用登入，CIK 欄可以直接填代號）

| 來源 | 網址格式 | 說明 |
|---|---|---|
| 8-K（美國公司重大事件） | `https://www.sec.gov/cgi-bin/browse-edgar?action=getcompany&CIK={代號}&type=8-K&count=10&output=atom` | 每則有 title、filing-date、filing-href（申報索引頁）、items-desc（例如 item 2.02）、accession-number |
| 6-K（外國公司在美申報，例如 TSM） | 同上，`type=6-K` | 沒有 items-desc，要看標題 |

- 識別碼＝accession-number
- SEC 要求程式帶 User-Agent；抓網頁工具被擋（403）時，在心跳寫「讀取失敗：SEC 403」，不要一直重試

### 新聞 RSS（台股、美股都用）

| 來源 | 網址格式 | 說明 |
|---|---|---|
| Google News 英文 | `https://news.google.com/rss/search?q={英文名或代號}&hl=en-US&gl=US&ceid=US:en` | 美股用；title 結尾是「- 媒體名」 |
| Google News 中文 | `https://news.google.com/rss/search?q={中文名}&hl=zh-TW&gl=TW&ceid=TW:zh-Hant` | 台股用，也可以查美股的中文報導 |
| Yahoo Finance | `https://feeds.finance.yahoo.com/rss/2.0/headline?s={代號}` | 美股備援，常混大盤新聞 |
| Yahoo 奇摩股市 | `https://tw.stock.yahoo.com/rss?s={代號}` | 台股備援，常混大盤新聞 |

新聞篩選（哨兵照規則做，不自己判斷重不重要）：
- 只記 24 小時內的（看 pubDate，換成台灣時間再判斷）
- 每個來源每次最多 10 則
- **標題要含公司名稱、簡稱或代號**才記（避免大盤新聞洗版）
- 同一事件多家媒體報導，標題幾乎一樣的只記第一則
- 識別碼＝guid（沒有就用連結）
- 鉅亨網 RSS 已失效，不要用；Google News 中文的結果會包含鉅亨網

## 三、記錄：用 OpenBot 共用資料庫（不用整檔重寫）

已看過的消息存在共用資料庫的表 `stock_inbox`，**不要用檔案記已讀**（新聞一多檔案就上百 KB，整檔重寫又慢又容易出錯）。工具：`openbot.list_tables`、`openbot.query_data`、`openbot.execute_data`（一次一個 SQL、值一律用 `?` 參數）。

第一次（list_tables 沒有這張表）建立：

```sql
CREATE TABLE stock_inbox (
  id TEXT PRIMARY KEY,      -- 識別碼（重訊：代號｜日期｜時間；SEC：accession；新聞：guid 或連結）
  market TEXT, ticker TEXT, company TEXT,
  source TEXT,              -- 重訊／8-K／6-K／新聞
  title TEXT, url TEXT,
  published TEXT,           -- 台灣時間 YYYY-MM-DD HH:mm
  found_at TEXT,            -- 台灣時間
  status TEXT               -- 待判讀／已判讀／略過
)
```

每次巡邏：
1. 每家公司、每個來源取項目（新聞每個來源最多取 **10 則、24 小時內**；公告與申報取最近 10 則）
2. `SELECT id FROM stock_inbox WHERE id IN (?, ?, …)` 找出已經記過的
3. 沒記過的才是新的：一次寫入多列，`status` 填「待判讀」
4. **第一次建表、或清單新加了一家公司時**：這家公司各來源讀到的**全部項目**都寫入、`status` 一律填「略過」、不轉交（避免把舊新聞當新消息）
5. 同一輪新消息超過 20 則時，只把公告與申報（重訊、8-K、6-K）和最新 10 則新聞標「待判讀」，其餘標「略過」，心跳寫「新聞過多，只送最新 10 則」

`~/OpenBot/Shared/投資/個股哨兵/心跳.md` 照舊每次追加一行（讀出整檔、加一行、整檔寫回；心跳檔很小沒關係）：台灣時間｜各來源讀到幾則｜新增 N 則｜已轉交／無新增／轉交失敗。

## 四、轉交

有新消息時，用 `openbot.tool_call` 的 `send_message` 請「投資情報分析員」執行例行任務「個股快評」。**排程中不能用 test_routine 觸發別的代理**（會被擋），一定用 send_message。失敗就在心跳寫「轉交失敗：原因」，情報分析員每天 08:00、20:00 也會自己補判。

## 五、個股快評格式（投資情報分析員）

每則消息寫成一段：

```
★★★★☆ 4／5｜NVIDIA（NVDA）｜利多（推論）｜信心：中
事件：（一句話，照原文，不加料）
判讀：（兩三句：為什麼可能是利多／利空，傳導到營收、獲利、估值或風險的哪一塊）
要注意：（反向的可能、市場是否已預期、還不知道的事）
來源：原文網址（公告或申報本身，不是新聞列表）＋至少 1 家新聞報導網址
```

依星等由高到低排列；★★★★★ 的放在回覆第一行。

**信心度**：高＝有公告或申報原文、數字明確；中＝有原文但影響要靠推論；低＝只有媒體報導或資訊不完整。**資料不足以判斷方向時一律判「中性」並把信心寫「低」**，不要硬給利多利空。

把消息分成兩類：會改變公司獲利、風險或你原本看法的「重要事件」，和例行公告、重複報導的「雜訊」；雜訊合併成一行帶過。這一輪都是雜訊時寫「無重大消息」。

## 六、利多／利空／中性怎麼判

只有三種結論，一律標「推論」：

| 結論 | 什麼時候用 | 例子 |
|---|---|---|
| 利多 | 事件可能讓公司未來營收、獲利、現金流變好，或風險變小 | 財測上修、拿到大訂單、月營收創新高且高於去年同期、取得重要認證、和解結束訴訟 |
| 利空 | 可能讓營收、獲利、現金流變差，或風險變大 | 財測下修、主要客戶流失、大額罰款或訴訟敗訴、停工、財報被要求重編、高階主管突然離職 |
| 中性 | 例行事項、影響很小，或多空力量相當、方向看不出來 | 股東會議事程序、例行董事會、法說會日期公告、澄清媒體報導但沒有新事實 |

判讀時一定想到這三件事：
1. **市場是否已預期**：財報「創新高」但低於市場預期，股價可能反而跌；寫「若市場預期更高，可能被視為利空」
2. **規模**：金額占營收或市值多少？很小的合約寫「影響有限」，不要因為標題聳動就給利多
3. **一次性還是持續**：處分資產的一次性利益、匯兌收益，不等於本業變好

不寫目標價、不寫漲跌幅預測、不寫「建議買進／賣出」。

## 七、重要性星等（這家公司）

| 星等 | 事件 |
|---|---|
| ★★★★★ 5 | 可能明顯改變公司價值：財測大幅上修或下修、併購或被併購、減資增資、下市或停止交易、破產重整、重大訴訟判決或巨額罰款、主要客戶或供應商流失、重大事故停產、財報不可依賴或重編 |
| ★★★★☆ 4 | 重要：每季財報、月營收年增或年減 20% 以上、股利政策大改、大額資本支出或新廠、重要合約或客戶、執行長或財務長異動、信用評等調整 |
| ★★★☆☆ 3 | 一般：法說會內容、庫藏股、一般合約、新產品發表、董事會一般決議 |
| ★★☆☆☆ 2 | 例行：股東會議事程序、一般人事、澄清報導但沒有新事實 |
| ★☆☆☆☆ 1 | 與公司價值幾乎無關，或是重複報導 |

**美股 8-K 常見項目對照**（items-desc 的編號）：
- 1.03 破產或接管、3.01 下市或不符上市標準、4.02 先前財報不可依賴 → ★★★★★
- 2.02 財報與營運結果、1.01 重大合約、2.01 完成併購或處分、5.02 董事或高階主管異動 → ★★★★☆
- 7.01 公平揭露（Reg FD）、8.01 其他事件 → 看內容，通常 ★★★☆☆
- 5.07 股東會投票結果、9.01 只附財報附件 → ★★☆☆☆

調整：
- 和使用者持股直接相關，加一顆，最多五顆，並寫「這是你的持股」
- 只有一家媒體報導、還沒有公告或申報佐證：最多三顆，標「未證實」
- 同一事件 24 小時內已判讀過：標「重複」，沿用原星等，不另寫一則

## 八、易錯點

- 哨兵用新版 mops.twse.com.tw：讀不到內容，要用 mopsov 或 OpenAPI。
- 第一次只讀了 RSS 的前幾則就記已讀：下一次讀到後面的舊新聞會全部當成新的。第一次要讀完、全部標「略過」。
- 用檔案記已讀：新聞一多就失控，改用 stock_inbox。
- 把大盤新聞記成個股消息：標題沒有公司名稱或代號的不記。
- 美股時間沒換算：SEC 的 filing-date 是美東日期，台灣時間可能是隔天。
- 只看標題就判讀：一定打開原文（公告、申報索引頁裡的主文件），標題常常誇大。
- 把「創新高」直接判利多：要看和市場預期、去年同期比。
- 用 test_routine 轉交：排程中會被擋，用 send_message。
